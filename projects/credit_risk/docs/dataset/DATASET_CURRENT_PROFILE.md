# Credit Risk Monitoring：最终版数据说明

更新日期：2026-09-14。统计依据为发布目录 `projects/credit_risk/dataset/expansion/releases/2026-09-14-eligible-trajectories-v1/` 的实际文件及 `manifest.json`。

## 任务与统计单位

目标是连续观察一家公司的公开信息轨迹，判断 Agent 能否在已核验风险事件发生前给出有依据的预警。独立评测单位是公司观察窗口；观察记录是窗口内有新材料公开的一天，不是独立的分类样本，也不补齐无材料日期。不需要逐日风险等级标签。

## 构建过程

1. **建立公司候选池。** 通过公司身份、CIK 和事件候选记录确定公司与观察窗口；候选清单只用于发现与复核，不直接作为最终标签。
2. **收集公开证据。** 利用 GDELT 新闻发现、已缓存新闻正文及 SEC 8-K/8-K/A 等申报资料；后续通过 Web Search 定向补充一手事件来源与核验依据。搜索命中不能直接当成新增全文或已核验标签。
3. **实体与时间对齐。** 匹配对应公司，按材料公开日期限制输入窗口；去重并清理正文噪声，保留材料来源、ID 和表示类型。无法取得正文的材料明确保留为标题表示。
4. **形成时间轨迹。** 将同一公司窗口内的材料按公开日组织成 observations，供逐步输入和 memory 累积；事件结局单独存放于 outcomes，不能作为输入泄漏给 Agent。
5. **核验事件并划分集合。** 父版本按公司随机划分 dev/test 6:4，固定 seed=42，要求共享证据组不跨集合。
6. **筛选最终评测轨迹。** 从父版本 107 条中保留 53 条，移除 54 条不符合当前目标规则的记录。同步过滤观察、公司清单、结局和相关侧表；保留内容及原集合归属，不重新抽样。

最终筛选由 `dataset/builders/build_r19_eligible.py` 实现，直接复用后端 `label_for` 的资格规则：结局状态为 `event_verified`；事件属于三个目标破产类型；事件主体范围以 `registrant` 开头；事件日期严格晚于窗口结束日。

父版本包括未充分核验的随访窗口、不同监控目标的状态变化窗口及其他不符合事件类型/主体/日期条件的记录。移出最终版表示它们不符合**当前评测定义**，不表示所有材料内容都是错误的。原 107 条版本已在项目外归档，见 [清理记录](../../dataset/CLEANUP.md)。

## 划分与可报告指标

当前 dev 30 条、test 23 条，继承原划分，**筛选后不再是严格 6:4**。没有根据模型得分调整集合。若 test 曾参与 prompt 调整，应如实披露，不能因为筛选就声称恢复成完全未见测试集。

可报告目标事件发现率、首次有效预警提前量及证据质量；漏检必须保留在分母中。比较 memory 增益需要在相同轨迹、输入和模型配置下进行对照。现有 Evolve 使用窗口结束时的快照，不能直接等同于逐日推进的 memory 评测。

由于没有已核验负例，不能据此报告整体二分类 accuracy、误报率或一般企业群体中的风险识别能力。资格筛选不是完整材料质量审计：仍存在稀疏轨迹、标题信息不足和行业分布不均。这里的数量不能用来证明风险出现前的信号一定充分。
