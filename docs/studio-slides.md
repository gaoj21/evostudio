# EvoAgentX Studio 介绍 PPT 提纲

共 5 页：动机 → 分层架构（功能）→ 相比纯写代码的优势。

---

## 1. 封面

**EvoAgentX Studio**：从数据到评估、再到自动优化的 Agent 工作流平台。
（通用平台；信用风险监控只是跑在上面的一个项目。）

---

## 2. Motivation

纯写代码做 Agent 工作流的问题：

- **迭代慢：** 改 prompt、调流程都要改代码、重跑脚本。
- **看不见：** 多节点、大批量、带记忆的流程，出了问题难定位。
- **难控制：** 停不下来、失败不重试、中断不能续跑，成本事后才知道。
- **不闭环：** 数据、记忆、评估、优化散落在不同脚本里。
- **协作难：** 懂业务的人参与不了。

---

## 3. 架构：分层

```
┌────────────────────────────────────────────────────────┐
│ 交互层   画布编辑 · 运行动画 · Chat 助手 · 结果与用量面板  │
├────────────────────────────────────────────────────────┤
│ 优化层   Evaluation（代码评估） · Evolve（自动优化 prompt）│
├────────────────────────────────────────────────────────┤
│ 执行层   按节点分批执行 · Stop / 重试 / 续跑 · 运行记录   │
├────────────────────────────────────────────────────────┤
│ 数据层   DataLoader（按时间分批） · 记忆（table / 向量）  │
├────────────────────────────────────────────────────────┤
│ 模型层   llm 包：统一接口，DeepSeek / SafeChain 可替换    │
└────────────────────────────────────────────────────────┘
        + 项目插件（数据源、模板、工具），让平台保持通用
```

---

## 4. 各层做什么

- **交互层：** 在画布上搭流程；运行时看到当前节点和数据流向；Token 和费用实时显示。
- **优化层：** 评估用自己的 Python 代码；Evolve 在 dev 上优化，在留出的 val 上验证，每轮使用独立的记忆。
- **执行层：** 大批量按节点、按批次有序执行；随时可停，临时错误自动重试，中断后可续跑。
- **数据层：** 数据集用 Python 代码定义；记忆按实体和时间隔离，不会用到未来的信息。
- **模型层：** 换模型供应商不用改平台代码。

---

## 5. Advantages over pure coding

| 纯写代码 | EvoAgentX Studio |
|---|---|
| 改代码、重跑脚本 | 画布上直接改 |
| 翻日志定位问题 | 实时看到每个节点的输入和输出 |
| 自己写并发、重试、续跑 | 平台内置 |
| 手工试 prompt | 自动优化，并在独立数据上验证 |
| 事后对账 | 成本实时可见 |
| 只有工程师能改 | 业务人员也能参与 |

**不是低代码的妥协：** 数据集、工具、评估仍然是完整的 Python 代码，平台负责其余的工程工作。
