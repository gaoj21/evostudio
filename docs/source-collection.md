# API 输入采集与批量运行

在 Run workflow → Batch run 选择 Canvas source node config。API 输入可以选择两种执行模式：Collect everything, then run（全量采集后运行），或 Run each batch as data arrives（边采集边运行）。全量模式先显示 Collect data；新闻源可在该处选择起止日期，以及每条运行对应一天、一周或一个月。采集进度与 Workflow 运行进度分开：全量模式采集完成前不能 Run batch。完成后显示保存的记录数和前三条输入预览，再运行确认的批次。

## 数据流

`source_collection.py` 将采集放在可终止的独立进程中。采集任务状态和完成后的记录保存在配置数据目录的 `collections/<id>.json` 中。预览和运行提交同一个 collection_id，从这份快照读取数据，不再访问新闻 API。批次本身也保存映射后的输入。源节点配置改动后，旧快照不能运行；如果预处理删除了已声明的源输出，也会拒绝运行，避免执行时偷偷重新抓取。

浏览器记住当前任务最近的采集 ID，重新打开 Batch run 可查看采集进度或复用已完成数据。停止采集会终止采集进程；失败、停止或重启中断的采集不可用于运行。已完成的数据能在服务重启后复用。

## 新闻源

GDELT 按所选时间窗口采集，按时间顺序生成记录，跳过没有新闻的窗口。每日、每周是从起始日期划分；每月按自然月边界划分。起止日期都包含在请求范围内。每个窗口的一条记录包含 company、news_batch、window_start、window_end、n_articles；批次额外保留 sample_id 和 as_of，使同一公司的窗口按先后顺序执行。

采集使用 API 的 250 条返回上限，触顶时把时间窗口继续拆分；若一天仍触顶，采集失败并要求缩小查询，不将截断数据标为完整。保存的是 API 提供的新闻标题和链接，不是文章全文，也不保证 API 未收录的新闻可被采集。此版本单次最多选择一年。

GDELT API 参数参考：[官方 DOC API 文档](https://blog.gdeltproject.org/gdelt-doc-2-0-api-debuts/amp/)。采集按小窗口请求，避免长区间的结果数量上限造成静默遗漏。

## 其他输入与范围

自定义 Source 返回的记录列表同样可以先采集后批量运行。HTTP API 在 Inspector 设置 Batch records = items，并用 Extract 定位 JSON 数组，就能每个数组元素运行一次；完整元素保存在 api_response，不受单次读取的 8000 字符截断影响。通用 HTTP API 的自动翻页尚未实现，它采集的是这一次响应里的数组；需要多页的服务目前应使用实现翻页的自定义 Source。

目前批量采集要求一个已连接且启用的 Source；多个输入源的关联规则不能靠名称或列表位置猜测，因此会明确提示先合并数据源。已有本地 credit risk Feed 保留原来的预览和运行入口。


## 边采集边运行

选择 Run each batch as data arrives，设置 Records per batch（1–1000），点击 Start collecting and running。GDELT 每完成一个非空时间窗口就传回一条记录；达到阈值立即启动一个批次，同时采集进程继续抓取后面的窗口。各批次顺序执行，前一批成功后才执行后一批，保留跨批次的时间顺序。采集结束后不足一批的尾部记录也会运行。

界面分别显示采集窗口进度、已收集/已提交记录数，以及每批的记录数和运行状态；View batch 可打开该批次。Stop collection and runs 同时停止采集和当前批次，已完成结果保留。采集或某个批次失败后，不再启动后续批次。已执行的流式采集快照不能再次通过全量 Run batch 入口重复执行。

整个流式过程使用启动时保存的工作流快照；执行中改画布不会影响后续批次。重新打开页面可以查看服务端仍在继续的采集/运行任务。服务重启后不会自动重放流式任务，避免重复执行已经产生副作用的步骤。

HTTP 数组、自定义 Source 的记录在其请求/函数返回后才可传回；只有能逐步产出数据的采集器（目前为 GDELT）能在整个采集尚未结束时启动首批。通用 HTTP 自动翻页与自定义生成器接口尚未实现。
