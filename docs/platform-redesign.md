# 通用任务平台改进

## 目标

平台服务任意领域的自定义任务。项目组织目标与任务，任务复用工作流执行引擎；评测、Memory 和领域结果视图按需使用。Credit Risk 是业务项目，不是首页默认任务或平台数据模型。

## 已实现（第一轮）

- 前端默认进入项目首页，不再自动打开最近的风险画布。
- 新建项目，按项目列出任务，将旧工作流显式归类。
- 通过名称、目标、预期输出创建通用单 Agent 工作流；运行时提供文本 input。
- 创建不调用模型；进入现有编辑器设置模型、工具、技能、Memory 和多步骤流程，再运行。
- 旧工作流保留在 Unassigned tasks，运行历史和图身份保留。
- 后端 `/api/projects` 创建/列表，`/{id}/tasks` 创建/列表，`/{id}/tasks/{graph_id}` PUT 归类。
- 项目使用独立 UUID；新任务记录稳定 task_id，graph_id 继续遵循旧重命名规则。图保存和改名保留归属信息。
- 项目文件保存在 studio-data/projects，任务执行定义仍在 studio-data/graphs。项目是组织关系，不是权限隔离。

## 验证与边界

769 项后端/数据测试、339 项前端测试通过，前端生产构建通过。未进行付费模型验证，不代表任意生成任务的实际答案质量已验证。

第一轮任务打开后使用现有高级编辑器；第二轮已将工作流选择器限定为当前项目。项目编辑、归档、资源页面与跨实验结果页尚未实现；独立任务详情已在第二轮加入；不展示不可用的导航占位按钮。项目分类不自动移动已有文件和 memory，不改变已有调度。

## 后续顺序

1. 任务详情：目标、输入、模型、产物、最近运行；画布成为高级编辑视图。项目内导航与新建、导入保持归属。
2. 项目资源：文件、数据、工具、技能的通用注册与选择；领域扩展显式启用。
3. 实验与评测：固定工作流/输入/模型版本，通用自定义评分、批量与配置对比。
4. 调度可靠性：持久化执行状态、检查点、预算与可控重试；组内顺序执行作为通用策略。
5. Credit Risk 接入轨迹回放与事件评分，验证上述能力，不在通用平台中硬编码风险概念。

这些是后续范围，不是本轮完成声明。

## 第二轮：任务详情与项目内操作

- 打开任务先显示目标、实际运行输入、步骤数、工具/技能和最近 20 次运行。
- 查看历史结果不会重新执行；有运行中的记录时自动刷新列表。
- “准备运行”进入现有运行确认流程；“编辑工作流”进入高级画布。
- 输入和可运行状态来自服务端执行计划；校验失败仍可编辑，但不能从详情页准备运行。
- 编辑器工作流列表按当前项目筛选；新建、导入和套用模板在已归类项目中自动关联项目。
- 创建任务后进入详情页，不再直接进入画布。

模型仍沿用平台已有配置，详情页不虚构具体型号；Memory 逐步骤编辑。任务详情目前展示单次运行记录，完整批次对比仍在现有 Runs 面板。没有新增自动执行，也没有运行付费模型。

## 第三轮：运行功能与材料输入（2026-09-09）

本轮优先打通材料输入和实际执行，适用于所有项目。

- 单次运行的文本/结构化字段可从本机读取 TXT、Markdown、JSON、CSV、TSV、LOG；保留原文，替换指定字段后可检查和编辑。限制为 UTF-8、1 MB；不截断材料。PDF、Word 尚不支持。
- 文件读取在浏览器本地完成，点击运行才提交内容。空文件、二进制、编码错误或不符合字段类型时保留原输入并阻止误运行；手动编辑会撤销未完成的读取，避免异步结果覆盖新输入。
- 同一图版本及起点的本地保存输入优先，历史运行仅补充缺失字段，避免新材料被旧结果覆盖。
- 数字输入拒绝无穷值及 JavaScript 无法精确表示的整数。
- 只有实际参与执行的 Agent 才触发模型初始化；本地工具流程无需先配置模型。工具依赖环境检查仅针对本次执行的 Agent。
- 从中间步骤启动时不探测被跳过的上游数据源；全图的结构校验仍保留。

验证：351 项前端测试、755 项后端 Studio 回归通过；随后新增的跳过数据源接口测试所在测试文件 27 项通过。生产前端构建通过。验证包含文件内容实际提交、读取失败保留输入、本地工具执行不初始化模型、跳过的 Agent 不检查其工具依赖。未调用付费模型，也未验证模型答案质量。

本轮没有实现精确检查点恢复、PDF/Word 解析或统一项目文件库；从中间启动仍是使用明确输入的一次新运行，并非原运行的检查点续跑。

## 第四轮：Agent 记忆读写与自定义配置（2026-09-09）

### 生效规则

- 保留 `use_long_term_memory` 总开关。新增 `memory.read_enabled` 与 `memory.write_enabled`；旧配置缺省均为 true，保持兼容。
- 关闭 read_enabled：不读取长期记忆，也不注入 session 历史。关闭 write_enabled：不写长期记忆，也不追加 session 记录。两者独立，可只读、只写或读写。
- `read_from: null` 表示自己的存储；`read_from: []` 表示不读取任何长期记忆来源。空列表不再在表格查询中回退为自身。Session 历史由读取开关及 session_recall 控制，不属于 read_from。
- 只读 Agent 不创建自己的向量存储；可读取已有存储，即使自身没有存储也会挂载读取钩子。导出工作流同步支持这些规则。
- 画布 Memory → Agent 连线开启读取。此前未开启记忆的接收方默认只读，继承来源的存储类型、对象键与时间字段；已有接收方保留自己的写入选择。
- 关闭写入隐藏写入连线，关闭读取隐藏读取连线。保留历史存储节点，明确标注写入关闭，不删除历史数据。
- 表格/向量类型不一致或表格对象键不同，在运行计划中提示；本轮不提供跨存储类型转换，也不把提示当作已经成功读取的证明。

### 自定义与说明

编辑 Memory 时合并原有配置，保留 kind、limit 及其他自定义字段。新增记忆字符预算编辑，后端现有范围为 200–20000。选择新的存储方式时显式更新 kind。修正工具节点“必须先于 Agent 执行”的旧说明；实际按连接关系执行。记忆错误提示改为“读取或写入失败”，不再将读取失败一律描述为写入失败。

### 验证和范围

764 项后端 Studio 测试通过。前端全量 355 项中 354 项通过，唯一失败是旧错误提示文案断言；更新断言后对应文件 7 项通过。生产构建通过，未调用付费模型。新增验证覆盖只读跨节点召回进入真实框架 Action 的提示词、关闭读取跳过会话与长期历史、只读不写入、不创建存储、空读取来源、配置保留、画布连接及读写方向、运行计划兼容性提示。

本轮仍保留“Agent 附属存储”的架构，没有引入独立共享资源库、逐 Agent 模型覆盖或最终提示词预览。记忆仍在整轮执行结束时保存；同一轮节点间传递结果使用工作流输入输出。这些是后续范围，不是本轮完成声明。

## 第五轮：Mem0 项目共享记忆

接入 Mem0 OSS 2.0.20，以独立空间提供同项目跨任务记忆。现有 Agent 执行器通过适配层读取与保存，不更换执行框架。前端增加空间选择及管理入口；原节点记忆和精确时间表继续保留。默认本地嵌入、原文写入，无额外提取模型调用。详细使用方法、API、数据位置与当前限制见 [Mem0 接入说明](mem0-integration.md)。

验证：接入后的既有后端 764 项、前端 355 项全量回归通过；新增 Mem0 后端 9 项通过，新前端管理入口 3 项通过，最终前端相关 71 项通过；运行器相关追加验证 68 项通过。真实 Mem0 + 本地 Qdrant 临时库验证了跨任务共享、项目隔离、增删改查。生产构建通过，服务已更新。

## 第六轮：Memory 画布交互

Memory 不再点击后仅跳转到拥有者 Agent。Mem0 空间按 space_id 去重为独立资源，支持直接添加、拖动、双向连接、选择连线断开、资源级检查器与条目管理。连接修改实际 Agent 读写策略；不兼容连接明确拒绝。资源元数据与位置保存到图中，并纳入撤销/重做；删除展示不删除存储内容。旧节点存储保留兼容。详细交互规则见 [Mem0 接入说明](mem0-integration.md)。

验证：774 项后端回归通过；365 项前端全量回归通过，随后增加的资源连接/保存及撤销重做验证所在相关测试共 46 项通过。生产构建通过。实际浏览器确认节点库新增资源入口，未执行模型任务或改写现有记忆数据。
