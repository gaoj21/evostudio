# 页面助手的统一架构

画布助手和结果助手使用同一个 `/api/graphs/{graph_id}/assistant` 请求入口，通过 `context: canvas | results` 指定页面上下文。原有两个接口保留为兼容入口。

## 共用部分

- `backend/api/chat_engine.py`：模型响应解析、历史注入、多轮工具调用、观察结果反馈、执行上限和待确认动作的停止机制。
- `result_chat.scoped_records` 和 `result_chat.operate`：读取指定任务/批次/记录的数据、补全原始批次输入及标签、执行统计和 Python 计算。画布也注册了相同的 compute/aggregate 工具。
- `frontend/src/chatSession.js`：会话加载、保存、消息 ID 和多 Session 管理。沿用已有存储键，保留旧对话，页面切换不会覆盖另一页面的历史。
- `ChatComposer`：输入、发送、繁忙状态、Enter/Shift+Enter 与中文输入法处理。
- `ChatActivity`：工具结果、Python 代码、输出与错误展示。

## 页面适配

画布提供当前未保存的图、操作适配器以及生成任务/运行确认/验证修复的生命周期。结果页提供所选数据范围和数据操作适配器。它们不再各自实现模型工具循环，但保留页面特有操作及反馈。

画布与结果页各自按任务管理一份会话列表。结果数据范围保存在 Session 上下文中，切换记录不会切换会话；用户可以显式使用当前选中记录。旧范围消息携带上下文标记，避免当作当前计算的数据。

工作流里的独立 Chat Agent 是用户配置的执行节点，仍由 Deep Agents/LangGraph 执行，保存服务端 checkpoint；不把它的任务执行状态混入页面助手历史。

## Session

两个页面共用 `ChatSessions` 与 `useChatHistory`。每个任务页面可以创建多个会话，通过 Chat 容器内的侧滑面板搜索历史、选择历史继续、重命名及确认删除；面板覆盖当前 Chat 内部，不遮罩页面其他区域，也不挤压消息区高度。旧的按记录/批次拆分的结果历史会汇入统一列表并保留其数据上下文。旧的单段历史会迁移为首个 Session；刷新恢复上次选中的 Session。任务重命名会迁移画布 Session 集合。

会话目前保存在当前浏览器 localStorage，不是跨设备服务端同步。消息按 Session 保存，发送时仅选中的会话进入模型历史；模型侧仍使用最近 12 条上下文。执行过程中可以查看列表，切换/删除在当前操作完成后可用，防止正在生成的工作流或运行结果落到另一个 Session。

## 结果页布局

输入数据可以整体折叠，内部数据源可以分别展开。结果详情和 Chat 使用与画布相同的 react-resizable-panels，支持拖动、键盘调整和尺寸持久化；手机布局改为上下调整。

## 强制停止

两个页面共用 `useChatCancellation` 和输入区的 Stop 按钮。每次请求携带独立 request_id；停止接口设置后端取消标记，模型请求与工作流生成运行在可终止的子进程中，Python 计算也会终止进程组。工具执行前后检查取消状态，前端忽略已停止请求的迟到响应，原 Session 可继续提问。已完成的操作保留；通过聊天启动的独立工作流仍使用其运行停止入口。生成任务支持刷新后重新连接并停止。


## 验证

覆盖两个页面通过同一入口执行计算、工具错误反馈、运行确认停止、旧历史保留及隔离、输入折叠和可访问分隔条。原有画布生成、连续编辑和运行测试继续保留。
